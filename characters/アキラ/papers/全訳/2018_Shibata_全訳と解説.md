## 要旨（Abstract）

### 背景
命題密度（idea density; ID）は自然言語処理にもとづく指標で、英語の語りを分析して認知症の発見を助けるために開発された。しかし、文法上の概念を翻訳するのが難しいため、英語以外の言語には適用されてこなかった。本研究では、先行研究にもとづいて日本語の語りの中の命題（idea）を数える規則を定め、さらに機械翻訳を使って日本語テキストの ID を推定する新しい方法を提案した。

### 材料
参加者は、69〜98歳（平均 84.95歳）の日本人の認知症患者 42名だった。参加者から自由な語りを集めて音声コーパスを作った。患者の語りは、Google 翻訳、Bing Translator、Excite 翻訳の3つの機械翻訳システムで英語に翻訳した。そのうえで、英語用の ID 採点ツールである Dependency-based Propositional ID（DEPID）を使って、翻訳されたテキストの ID を計算した。

### 結果
DEPID-R-ADD（曖昧な文を除いてから ID を計算するように DEPID を改良した方法）で計算した ID と、ミニメンタルステート検査（MMSE）の得点との相関係数は、最大で 0.473 であり、中程度の相関を示した。

### 考察
結果は、機械翻訳にもとづく ID の測定が実現可能であることを示している。この翻訳を使うアプローチの基本的な考え方は、英語以外の他の言語にも応用できると考えられる。

## はじめに（Introduction）

平均寿命が着実に延びたことで、健康上・社会上の深刻な問題が生じている。長寿に伴う最も重要な問題の一つが、アルツハイマー病の発症率の上昇である [1]。日本の厚生労働省は、65歳以上の健康な人の4人に1人以上が、近いうちに軽度認知障害か認知症にかかると報告している。これらの患者がこの状態に対して医療を受けた場合、年間の介護費用の総額は10兆円を超えると推定されている。残念ながら、認知症は現在の医療では治らないが、早い段階で発見されれば、それ以上の悪化を防げる可能性がある。そのため、認知症を早期に発見するための技術を開発する必要がある。

さまざまな認知症のスクリーニング手法の中でも、患者の語りの分析にもとづく方法が大きな注目を集めている。Snowdon らは、人生の早い時期に ID が低いことが、晩年にアルツハイマー病を発症するリスクの上昇と結びついていることを見いだした [2]。ID はもともと Kintsch と Keenan によって開発されたもので、テキストや発話に含まれる命題（「idea」とも呼ばれる）の数を表す [3]。ID の計算には専門家による注釈づけが必要なため、多くの時間と費用がかかる。このため、ID を自動で推定するソフトウェアを開発した研究者もいる。たとえば Brown らは、品詞タグにもとづいて英語のテキストや発話の ID を求めるプログラムである Computerized Propositional ID Rater（CPIDR）を開発した [4]。また、Sirts らは、繰り返される命題や曖昧な文を除外できる Dependency-based Propositional ID（DEPID）の手法を開発した [5]。

CPIDR と DEPID の手法は、参加者を健常な統制群とアルツハイマー病または認知症の患者とに分類する研究で、すでに ID の計算に使われている。Jarrold らは、ID などの言語的特徴を使って、健常者とアルツハイマー病・認知症の患者を 73% の正確さで区別できたと報告した [6]。ID はまた、Roark らによって、物語の語り直し（story re-telling）のデータセットから軽度認知障害を検出するためにも使われた [7]。

先行研究は、医師の診断にもとづいて分類された認知障害の患者と健常者の ID を調べてきたが、我々の知る限り、ID とミニメンタルステート検査（MMSE）の得点との相関は調べられていない。ID は、認知障害そのものよりも、MMSE で測定できる注意や計算能力といった認知機能とより関係しているかもしれない。本研究は、この知識の空白を埋めることを目指して、ID と認知機能の関係を対象とする。

ID はこれまで日本語の文脈で使われたことがないため、本研究では日本語における ID を定義し、ID と認知機能の相関を示すことで、この言語での妥当性を調べる。さらに、日本語の語りの ID を使った認知症スクリーニングの可能性も検討する。

> 💬 アキラ：「命題（idea）」っていう単位が出てきたね。これは Kintsch の流れの「意味の単位」で、文字数や単語数とは違う。瀬島君の記憶課題でいえば、「どれだけ書いたか」じゃなくて「どれだけの中身を書いたか」を数える単位なんだ。ID はその命題の数を語数で割った「密度」だけど、私たちにとっては**分子の「命題の数」そのもの**のほうが、記憶量の指標として参考になるよ。

## 日本語の命題密度の計算

ID は、命題の数を数え、その合計をテキスト中のトークン数で割って計算した。トークン数と命題数の数え方を以下に述べる。

### トークンの数え方

トークンは、日本語の形態素解析器（Juman++）を使って抽出した [8]。解析器は、Chand らが提案した方法 [9] にもとづいて、次の品詞を抽出した：名詞、動詞、副詞、イ形容詞（例：赤-い "red"）、ナ形容詞（例：静か-な "quiet"）、連体詞（例：いかなる "any"）、接続詞、感動詞〔原文は emotive verb〕。

なお、日本語のトークンを数えるのに、本稿では「形態素（morpheme）」という用語を使う。英語のデータでは、英語の文の単語は一般にスペースで区切られているため、トークンを数えるのに普通は「単語（word）」という用語が使われ、単語をトークンとして使いやすい。それに対して、普通の日本語の書き方では、単語はスペースで区切られていない。日本語の文をトークンに分割するために、我々は Juman++ や MeCab [10] といった日本語の形態素解析器を使って文を分割した。本稿では、形態素解析器の出力の一つ一つを「形態素」と呼ぶ。例：Watashi/ha/akai/ringo/wo/nageta（「私は赤いりんごを投げた」）。ただし、形態素解析器の出力としての形態素の定義は、言語学でいう形態素の概念とそのまま対応するわけではない。前者は後者より少し大きい（たとえば、前者は akai を1つの形態素として区切るが、後者はこれを aka/i の2つの形態素に区切る）。このように、我々が形態素解析器の出力として使う形態素は、おおむね単語に相当するとみなせる。

> 💬 アキラ：**ここがこの論文で一番大事なところ！**　よく読むと、日本語側で数えたのは「名詞・動詞・副詞・形容詞・連体詞・接続詞・感動詞」だけなんだ。つまり**助詞（は、を、が）や助動詞は数えてない**。一方で英語側（あとで出てくる）は、Stanford Parser のトークンだから、冠詞や前置詞も含めて全部数えてる。
>
> だから「日本語1 : 英語1.85」っていう比は、「**日本語の内容語の数** : **英語の全部の単語の数**」の比なんだよ。瀬島君の「日本語の文字数 : 英語の文字数（か単語数）」とは、分子も分母も違う。この数字を「日本語1文字＝英語◯文字」の根拠にそのまま使うことはできないんだ。
>
> ただ、考え方は使える。**「何を数えるか」を決めた瞬間に比が決まる**、っていうこと。だから瀬島君の研究でも、比を借りるなら「同じ数え方で出した比」を借りないといけないんだよね。

### 命題の数え方

本研究で使った注釈の規則は、大部分が Chand らのマニュアル [9] にもとづいている。そのマニュアルによれば、命題は叙述（predication）、修飾（modification）、接続（connectives）から成る。フィラー、笑い、聞き取れない発話、繰り返し、部外者の発話、部外者に向けた発話には注釈をつけない。しかし、根本的な文法の違いのため、英語用に作られた規則は、いつもそのまま日本語に適用できるわけではない。そこで、この方法を日本語のテキストに合わせるため、いくつかの新しい規則を加え、元の規則の一部を修正した。規則の詳細は S1 Appendix を参照。

日本語テキストの命題の数は、言語学者が手作業で数えた。

> 💬 アキラ：「フィラー、繰り返し、部外者への発話は数えない」っていうルールは、瀬島君の検討中の問い「間違った内容・繰り返し・感想はどう扱うか」にそのまま使えるね。Berman & Slobin も課題へのコメントは除いてた。**「数えないもの」をマニュアルに明記する**のは、どの分野でも共通のやり方なんだ。
>
> それと、英語の規則が日本語にそのまま使えないから日本語用に修正した、っていう話。瀬島君が節のマニュアルを作るときも、英語と日本語で同じルールにはできないから、「対応する規則」を両方の言語で作ることになると思う。この論文の S1 Appendix（日本語の命題の数え方の規則）は、手に入れる価値があるよ。

## 実験1：機械翻訳を使った命題密度の計算

テキスト中の命題に注釈をつけるには、言語の専門家による詳しい分析が必要なため、かなりの時間と費用がかかる。そこで我々は、日本語から英語への機械翻訳を使って ID を自動で計算する方法を提案する。この方法は、先行研究 [5] で述べられた手順（DEPID）にもとづいて、機械翻訳されたテキストの命題の数を自動で計算する。提案法を検証するため、人間の評定者が数えた命題の数（J-ID）と、DEPID で数えた命題の数（D-ID）を比べた。加えて、ID の計算に影響しうる、元の日本語テキストと翻訳された英語テキストのトークン数の違いも調べた。

### 方法

#### 倫理に関する記述
京都大学医学部附属病院の倫理委員会は、代諾による同意の取得を含めて本研究を承認した（承認番号 C1152、2016年4月28日）。すべての参加者、またはその代諾者から、書面によるインフォームドコンセントを得た。患者が自律的に同意する能力を欠く場合には、厚生労働省の「人を対象とする医学系研究に関する倫理指針」に従って、代諾者から同意を得た。各参加者の自律的な能力は、面接の前に、医師の診断と心理士による心理検査（MMSE）を考慮して、医師が評価した。参加者の募集は 2016年5月から10月に行った。参加者全員に、参加が任意であること、データが秘密として扱われること、参加を取りやめられることを書面で伝えた。

#### 英語の命題密度を自動で計算する方法
英語のテキスト用に、ID を自動で計算する方法がこれまでに2つ開発されている。CPIDR [4] と DEPID [5] である。

**CPIDR**
CPIDR は、英語のテキストから ID を自動で計算するツールである。このツールはまず品詞タガーでテキストを処理し、すべての動詞、形容詞、副詞、前置詞、等位接続詞を命題として数える。その後、37の規則を適用して最終的な命題の数を調整する。ID は、命題の数を合計し、単語トークンの数で正規化して計算する。

**DEPID**
DEPID の手法は、依存関係の数を数え、それを単語トークンの数で正規化して ID を計算する。

#### 機械翻訳
CPIDR と DEPID は英語のテキスト用に設計されているため、3種類の機械翻訳を使って日本語のテキストを英語に翻訳した（表1）。その英語のテキストから、DEPID の手法で ID を計算した。

**表1　機械翻訳の種類**
| サービス | 方式 | 提供元 |
|---|---|---|
| Google 翻訳 | ニューラル機械翻訳（NMT） | Google |
| Bing Translator | 統計的機械翻訳（SMT） | Microsoft |
| Excite 翻訳 | フレーズベース機械翻訳（PBMT） | エキサイト |

本研究では、Sirts らが、この方法のほうが CPIDR より正確に命題を数えると報告していることから [5]、依存関係にもとづいて ID を計算した。

ID（D-ID）の計算には DEPID を使い、命題の数を数えてトークン数で割った。命題の数（D-ID の場合は特定の依存関係）とトークンの数は、Stanford Parser [11] で使われている方法にもとづいて数えた。

さらに、日本語の発話では文の主語が普通は省略される。日本語のこの特徴は、トークンの数や ID の計算に影響しうる。この違いを明らかにするため、元の日本語のコーパスの形態素の数（日本語の形態素解析器で計算）と、翻訳されたコーパスのトークンの数（Stanford Parser で計算）を比べた。

〔式 (1)：D-ID ＝ DEPID で数えた命題の数 ÷ トークンの数。PMC の本文では数式は画像で、テキストには含まれていない〕

> 💬 アキラ：**「元の日本語の形態素の数」と「翻訳された英語のトークンの数」を比べた**、っていうのが私たちの欲しい部分。目的は「日本語は主語を省略するから、英訳すると量が変わるはずだ」を確かめること。瀬島君が考えた「日本語の模範記述を Google 翻訳して比を出す」案と、やってることはほとんど同じなんだよ。だからこの論文の結果は、その案を試したときに何が起きるかの予告編として読めるんだ。

### 結果

DEPID で数えた命題の数は、人間の評定者が数えた数とは違うと予想された。そこで、この2つの変数の相関係数と傾きを計算して、その関係を調べた。

表2は、機械翻訳の種類ごとに、DEPID で数えた命題の数と人間の評定者が数えた命題の数との相関係数と傾きを示す。人間の評定者による数との相関係数が最も高かったのは、Google 翻訳を使った DEPID の数（r = 0.983）だった。一方、回帰直線の傾きが最も1に近かったのは、Bing Translator を使った DEPID だった（α = 0.913）。図1と表3は、形態素の数とトークンの数の相関係数と傾きを示す。相関係数はどの機械翻訳でも一定（r = 0.995）であることを確認した。傾きは、Bing Translator を使ったものが最も1に近かった（α = 1.85）。

> 💬 アキラ：この表3が、私たちにとってのメインディッシュ！　読み取れることは3つあるよ。
>
> **1. 比例関係はものすごく強い（r = 0.995）。**
> 同じ人の語りの日本語の量と英訳の量は、ほぼ完全に比例するんだ。だから「日本語の量 × 定数 ＝ 英語の量」っていう**掛け算による換算の発想には根拠がある**。瀬島君の案1の大前提は、ここで支持されてると言っていいと思う。
>
> **2. でも、その「定数」は翻訳システムで 1.85〜2.46 も動く。**
> 同じ日本語なのに、訳し方が違うだけで定数が最大で約33%（1.85 と 2.46 の差）変わるんだ。仮に瀬島君がどれか1つの比を選んで換算したとするね。そうすると、別の比を選んでいたら日本人の参加者の得点は全員そろって最大3割くらい変わってた、ってことになる。前に話した「ノイズじゃなくてバイアス」の具体例だね。
>
> **3. 「r が一定なのに傾きが違う」ことの意味。**
> 相関が高いからといって、換算比が正しいとは限らないんだ。相関は「比例しているか」を教えてくれるけど、「何倍か」は教えてくれない。瀬島君が論文で換算比の妥当性を主張するときも、「相関が高い」だけでは足りなくて、「なぜその倍率か」の根拠がいるよ。
>
> あと細かいけど、本文では「Bing の傾き 1.85 が最も1に近かった」って書いてあるよね。でもトークン数の比は1になる必要はないから、ここの「1に近い」はあまり意味がないと思う。表2の命題の数の比較（本来1になるべき）と同じ書き方をしちゃったのかな。こういうところも批判的に読もうね。

### 考察

Bing Translator の結果から推定した傾きについては、約 10% の誤差があることを確認した（|観測値 − 真値| / |真値|。この場合、2つの方法で計算した命題の数は同じであるから、真値は1に等しい）。

単純な比較は適切ではないが、機械翻訳を使った我々の方法の結果には、先行研究 [4] のおよそ2倍の誤差があった。しかし、手作業と自動で数えた命題の数の間に強い相関があることは、この推定法がその単純さを考えればかなりの正確さをもつことを示している。

一方、元の日本語テキストの形態素の数と、Bing Translator で翻訳されたテキストのトークンの数との傾きを考えると、日本語テキストの1つの形態素は、翻訳された英語テキストのおよそ 1.85 語に相当することが分かった。この結果の理由として考えられるのは、手作業で命題を数える際に、日本語の発話では文の主語がしばしば省略されることである。

> 💬 アキラ：「日本語の1形態素 ≒ 英語の 1.85 語」って書いてあるね。でもさっき言ったとおり、日本語側は内容語だけ、英語側は全部の単語。だから 1.85 という数字の大部分は、たぶん「英語には冠詞や前置詞があるけど、日本語の数には助詞が入ってない」ことで説明できちゃうと思う。著者は理由として「主語の省略」を挙げてるけど、私は**数え方の非対称**のほうが大きいんじゃないかと思うな。瀬島君はどう思う？
>
> いずれにしても、「主語の省略」は瀬島君の研究にとって大事なポイントだよ。日本語の参加者は、映画の主人公を毎回「彼女は」と書かないよね。英語の参加者は毎回 She と書く。**同じ内容を覚えていても、英語のほうが長くなる構造的な理由がある**ってことなんだ。

## 実験2：命題密度の認知症スクリーニングへの応用

ID を使って認知症を発見することを目指し、ID と MMSE の得点との相関係数を計算した。

### 方法

Sirts ら [5] は、DEPID-R と DEPID-R-ADD という DEPID の改良版を開発した。以下にそれを述べる。我々は DEPID-R（DR-ID）と DEPID-R-ADD（DRA-ID）の両方で ID を計算した。図2は、元のコーパスから J-ID、D-ID、DR-ID、DRA-ID を計算する手順をまとめたものである。

**図2　さまざまな方法で ID を計算する手順**
〔図の説明：日本語の語りのコーパスから、(1) 言語学者が手作業で命題を数えて J-ID を出す流れと、(2) 3つの機械翻訳で英訳し、DEPID・DEPID-R・DEPID-R-ADD で D-ID・DR-ID・DRA-ID を出す流れを並べた流れ図〕

**DEPID-R**
Sirts ら [5] は、命題のタイプだけを数えることで、語りの中の重複した命題を除外するように元の DEPID を修正した。この修正版は DEPID-R と名づけられた。DEPID-R と DEPID の違いは、後者が同じ命題のトークンを数えるのに対し、前者は繰り返しの数を除外することである。DR-Ideas は、DEPID-R で数えた命題の数を表す。

〔式 (2)：DR-ID ＝ DR-Ideas ÷ トークンの数〕

**DEPID-R-ADD**
DEPID-R-ADD の特徴は、Speciteller というツール [12] を使って曖昧な文を除外する機能が加わったことである。認知症の患者の特徴の一つは、具体的な内容を含まない曖昧な文を発話することで、たとえば次のような例がある。
- 「上のやつはそこにある。」
- 「外側でもっといろいろやってる。」

DEPID-R-ADD は文の具体性を計算する。Sirts らの提案に従って、具体性の得点が 0.01 未満の文からは命題を数えなかった [5]。DRA-Ideas は、DEPID-R-ADD で数えた命題の数を表す。

〔式 (3)：DRA-ID ＝ DRA-Ideas ÷ トークンの数〕

次の4つの ID の値を比べた：J-ID（日本語で手作業で計算）、DEPID による D-ID、DEPID-R による DR-ID、DEPID-R-ADD による DRA-ID。

> 💬 アキラ：DEPID-R の「同じ命題は1回だけ数える」っていう考え方は、瀬島君の記憶課題でも使えるよ。参加者が同じ場面を2回書いたら、記憶量としては1回分だよね。文字数で数えると2回分になっちゃう。それに、「曖昧な文を除く」もそう。「いろいろあった」みたいな文は、文字数には入るけど記憶の中身はほとんどないよね。

### J-ID と MMSE
J-ID と MMSE の得点の相関係数は −0.039 で、2つの指標の間に相関はなかった。

### D-ID と MMSE
D-ID と MMSE の得点の相関係数の最大値は 0.294（Excite 翻訳）で、弱い相関を示した（表4）。

| Bing | 0.120 |
| Excite | 0.294 |

### DR-ID、DRA-ID と MMSE の得点
DR-ID と MMSE の得点の相関係数の最大値は 0.386（Excite 翻訳）で、弱い相関を示した。しかし、DRA-ID と MMSE の得点の相関係数の最大値は 0.473（Google 翻訳）で、中程度の相関を示した（表5）。

### 結果
J-ID と MMSE の得点の相関係数は −0.039 で、この結果から、これらの指標の相関は無視できるほど小さいことが確認された。D-ID および DR-ID と MMSE の得点の相関係数は、それぞれ 0.294 と 0.386（Excite 翻訳）で、これらの指標には弱い相関があることが確認された。DRA-ID と MMSE の得点の相関係数は、Google 翻訳で翻訳したテキストで 0.473 であり、これらの指標の間に中程度の相関があることを示した。

### ベースラインの指標との比較
我々の分析では、DRA-ID と MMSE の得点の相関係数は最大で 0.473 だった。DRA-ID の性能を調べるため、トークンの数（＝形態素の数）、名詞、動詞、形容詞、副詞、形容詞と名詞、副詞と動詞の数、およびタイプ・トークン比（TTR）を数えた。そして、MMSE の得点とこれら8つの言語的指標との相関係数を計算した。TTR は一般に、話し手の語彙の豊かさ（あるいはエントロピー）の代理指標とみなされ、テキストのタイプの数をトークンの数で割って計算する。タイプとトークンの数を数えるときは、内容語（名詞、動詞、形容詞、副詞）だけを数えた。表6は、MMSE の得点と言語的指標との相関係数、および無相関検定の p 値を示す。MMSE の得点と統計的に有意な相関があったのは DRA-ID だけだった（p < 0.05）。表6に示すように、MMSE の得点と8つの言語的指標との相関係数は、MMSE の得点と DRA-ID との相関係数よりかなり低かった。同じコーパスから他の言語的指標の結果を比べるのは難しいが、我々の指標は、単純な方法を使ったベースラインの指標を上回ることができた。

**表6　MMSE の得点と言語的指標の相関係数**（p 値は無相関検定による。* p < 0.05）
| 指標 | MMSE の得点との相関係数 | p 値 |
|---|---|---|
| DRA-ID | 0.473 | 0.002* |
| トークン | 0.153 | 0.330 |
| TTR | 0.021 | 0.900 |

>
> もちろん、これは認知症の患者さんの話し言葉で、映画の記憶課題とは全然違う。だからそのまま当てはめちゃダメだよ。でも、「**量（長さ）は、測りたい能力をそのまま反映するとは限らない**」っていう警告としては、ちゃんと受け止めたいな。
>
> 瀬島君の課題で文字数を記憶量の指標にするなら、「文字数が本当に記憶の中身と対応しているか」を一度確かめておくと安心だよ。たとえば、一部のデータで行為リストの得点と相関を取ってみるとかね。前に共同ノートに書いた提案3がそれ。

### 考察

J-ID と MMSE の得点の相関係数は −0.039 で、無視できるほどの相関しかなかった。しかし、D-ID、DR-ID、DRA-ID は、MMSE の得点とある程度の相関を示した。DEPID の手法で日本語のテキストから数えた命題の数は、人間の評定者が数えた数とおおむね一致していた。

調べた相関係数の中で最も高かったのは、DRA-ID（Google 翻訳）と MMSE の得点の 0.473 だった。対照的に、J-ID に最も近い方法である D-ID は、MMSE の得点と低い相関しか示さなかった。これは、認知症の発見という観点からは、曖昧な文がノイズになることを示している。Sirts ら [5] も、英語のテキストで曖昧な文がノイズになると報告しており、機械翻訳を使った我々の結果はその知見を裏づけるものである。我々の結果は、機械翻訳を使うことで、英語のテキスト用に設計された方法を日本語のテキストに適用できる可能性を示している。（曖昧な文を除いた）テキストの ID の検出は、Kintsch と Keenan [3] による元の定義と比べると発展してきたように見えるが、認知症の早期発見のための潜在的に有効な道具である。

日本語では文の主語を省略する傾向があるため、日本語の命題の数を自動で計算するのは難しい。この文の構造は、命題を数えるうえで重要な役割を果たす。英語の文は一般に主語を省略しないが、日本語の文は、次の例のように主語をしばしば省略する。

(1) 卵を食べる
　tamago-wo taberu
　卵-目的格 食べる-現在
　「（私は）卵を食べる。」
　1. 食べる、（私が）、卵を

しかし、機械翻訳で日本語から英語に翻訳すると、主語がしばしば補われる。したがって、我々は、機械翻訳を使って ID を計算するアプローチには、完全に自動の方法になる可能性があると考える。

さらに、翻訳エンジンの違いが ID の測定の性能に影響するかもしれない。まず、Excite 翻訳はルールベースの機械翻訳エンジンを使っており、文の構造を解析し、辞書を使って語を翻訳する。その結果、元の日本語で省略されていても、翻訳された英語の文に主語や目的語が入りやすい、整った翻訳になる。加えて、Excite 翻訳は、曖昧な意味の語の代わりにより明確な語を選んで翻訳できるため、他の方法より専門的な文章の翻訳に向いていると考えられ、これが ID の計算の性能を上げているのかもしれない。一方、統計的な機械翻訳とニューラルな機械翻訳は、曖昧な文を曖昧なまま翻訳する。こうした特徴が、Google 翻訳と Bing Translator を使った D-ID と DR-ID の性能の低さにつながった可能性がある。曖昧な文を除いた後（DRA-ID）は、これらの方法の性能は以前より良くなった。

> 💬 アキラ：**ここ、瀬島君の「Google 翻訳で比を出す」案に直結するよ。**
> - ルールベースの翻訳（Excite）は、省略された主語や目的語を全部補う → 英語が長くなる → 比が大きくなる（2.46）
> - ニューラル翻訳（Google）は、流暢さを優先して、曖昧なものは曖昧なまま訳す
>
> つまり、**機械翻訳で出した比は「その翻訳エンジンの訳し方のくせ」込みの数字**なんだ。瀬島君が心配してた「英語が模範的になりすぎる」っていうのは、まさにここで起きてること。ルールベースの翻訳ほど「教科書的な、全部言い切る英語」になって、長くなるんだよ。

表7は、各機械翻訳システムによる翻訳の例を示す。まず、比較的短い文である例 (a) では、どのシステムも適切な翻訳を返した。しかし、少し長くくだけた例 (b) では、Google 翻訳が他のシステムより良い翻訳を返した。対照的に、Bing Translator は文法的には正しいが意味のない文を返し、Excite 翻訳は意味の通らない文を返した。これらの例が示すように、Google 翻訳は一般に他のシステムより良い結果を出した。しかし、各機械翻訳システムの性質の一面を反映する例外もあった。例 (c) には、翻訳が難しい珍しい語である「鮒寿司（funazushi）」という語が含まれている。Google 翻訳の結果では、この語は無視され、対応する訳語がなかった。この例が示すように、Google 翻訳は知らない語を無視することがある。対照的に、他の2つのシステムは、知らない語を逐語訳（Bing Translator）または音訳（Excite 翻訳）で訳そうとした。したがって、Google 翻訳は結果の流暢さを優先し、他の2つのシステムは正確さを優先していると結論できるかもしれない。特に、Excite 翻訳が使うルールベースのシステムは、逐語訳（ときには音訳）を好むようである。Bing Translator は統計的機械翻訳にもとづいており、2つの方法のバランスをとる傾向がある。各翻訳システムの特徴の詳細は、それぞれの技術論文を参照。

**表7　各機械翻訳システムによる翻訳の例**
| | 元の日本語（ローマ字） | 人による翻訳 | Google | Bing | Excite |
|---|---|---|---|---|---|
| (a) | Eh chotto matte kudasai ne.（えー、ちょっと待ってくださいね。） | Well, can you please wait a second? | Well, please wait a minute. | Oh, wait a minute. | Please wait a moment. |
| (b) | Tabemono ha daitai nandemo tabe masu ne.（食べ物はだいたい何でも食べますね。） | I can eat nearly anything. | I do eat most of the food. | I usually eat food. | Everything almost eats food. |
| (c) | Ano funazushi to ka kirai yo.（あの、鮒寿司とか嫌いよ。） | I dislike that crucian carp sushi. | I mean, I hate it. | Carp, I hate sushi. | Uh, I don't like crucian carp ZU SHI. |

> 💬 アキラ：表7の例 (c) を見て。Google 翻訳は「鮒寿司」を**丸ごと落として**「I mean, I hate it.」にしちゃった。もし瀬島君の模範記述に、映画に出てくる珍しい物の名前があったら、Google 翻訳はそれを落として**英語を短くする**かもしれない。逆に Excite は音訳で無理やり残す。
>
> 1文の中でもこれだけ違うんだから、機械翻訳で比を出すなら**複数のエンジンを使って幅を見る**のと、**人の翻訳も1本は作る**のがいいと思うな。人の翻訳（表の「Translated by a human」の列）が、一つの基準点になるからね。

## 結論

本稿では、機械翻訳と命題の自動計数を使って、日本語の語りの ID を推定する方法を提案した。

また、ID と認知症患者の MMSE の得点との相関係数を計算することで、我々の方法の仕様を報告した。相関係数の最大値は 0.473 で、中程度の相関を示している。本研究は、機械翻訳にもとづいて ID を計算した最初の研究であり、日本語で命題を自動で数える方法の適用を確立するものである。

ここで我々は、日本語の語りの命題を数える方法を開発した。まず Bing Translator で対象のテキストを英語に翻訳し、次に翻訳されたテキストに DEPID の手法を適用することで、正確な数が得られる。また、認知症の発見のための4つの ID の計算方法を比較評価した。調べた中で最良の方法は、Google 翻訳で日本語のテキストを英語に変換し、それを DEPID-R-ADD で分析する方法だった。

先行研究は認知症の人と健康な成人の ID を比べてきたが、我々は、患者の言語能力と、その人自身の認知症の段階との関係を調べた。これらの知見は、我々の方法を、この病気の進行をモニタリングする測定ツールの開発に応用できることを示唆している。

本研究では、具体性の得点の閾値を、先行研究で使われたものにもとづいて設定した。したがって、このパラメータを変えたときの結果への影響を調べる必要がある。今後は、このパラメータを変えたときの影響を調べ、ロバストさを高めるために、自動翻訳と手作業の翻訳から計算した ID を比較するエンドツーエンドのシステムを実装する予定である。

> 💬 アキラ：最後の一文、「自動翻訳と手作業の翻訳から計算した ID を比較する」が今後の課題になってるね。つまり、**機械翻訳と人の翻訳でどれくらい違うかは、この論文ではまだ確かめられてない**んだ。瀬島君が模範記述で比を出すなら、そこを自分で確かめることになるよ。

## アキラのまとめ：瀬島君の案1にとって、この論文から言えること

| 問い | この論文から言えること |
|---|---|
| 掛け算で換算するのは妥当？ | **発想としては支持される**。日本語の量と英訳の量は r = 0.995 でほぼ完全に比例した |
| 換算比はいくつ？ | **この論文の数字はそのまま使えない**。日本語側は内容語の形態素だけ、英語側は全部のトークンを数えていて、文字数とは単位が違う |

| 機械翻訳で比を出す案は？ | 実質的にこの論文と同じことをやる案。翻訳エンジンのくせ（主語を補う、珍しい語を落とす）が比に入るので、複数のエンジン＋人の翻訳で幅を見るべき |
